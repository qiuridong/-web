## 失败时间线与根因

### run 48：换号前的冷启动等待不足

- App 冷启动 240 秒内仍被分类为 `unknown`。
- 当时还没有进入自动换绑。

### run 49：`pm clear` 后的 `am start -W` 假超时

- 已检测到配置账号变更，旧 App 数据和旧绑定已清理。
- 后续 `_launch_app` 使用 `am start -W`，ADB 在约 162 秒后报 `TimeoutExpired`。
- x86 Emulator 上的 arm64 NDK translation 首次初始化仍在继续，`-W` 超时不等于 App 启动失败。

### run 50 / 52：延迟公告和 Flutter 底栏丢触摸

- run `50` 最后界面是 `announcement`，run `52` 最后界面是 `home`。
- 原导航只点一次“我的”，公告延迟出现或 Flutter 吞掉首次触摸时没有状态机恢复。

### run 51：验证码自动换图消耗最后预算

- 已查看 18 张验证码；第 18 张是高置信乘法题，但在输入答案期间弹窗自动换图。
- 指纹复核正确阻止了过期答案提交，但旧 `for` 循环已无剩余图片预算，因而本轮直接结束。

### run 56：登录成功，但“已签到”被余额模板误判

- v1.2.2 的冷启动、公告/底栏恢复和验证码临界重试全部生效。
- 脚本查看到第 20 张时首次高置信题又自动换图，新宽限机制保留同一序号重试；下一张高置信题提交后登录成功。
- 新 AVD/账号/昵称字形三元绑定已写入，因此“换号登录失败”在这一步已被直接证伪。
- 后续任务页等待“已签到”超时。截图与分类分数证明：底栏和整体任务布局几乎完全匹配，首日奖励已显示勾选，但旧 `task-signed-top.png` 把顶部金币余额一并纳入固定模板。换账户后余额数字不同，`signed_score` 只有约 0.400，导致实际已签到页被判为 `unknown`。

## 实施

### v1.2.2：换号登录链路加固

1. `_launch_app` 去掉 `am start -W`，改为 30 秒非阻塞 Activity 启动，把完整就绪判定统一交给截图状态机。
2. `_navigate_my` 改为 45 秒有界状态机，可恢复延迟公告、登录/验证码残留界面和最多 6 次已知底栏丢触摸。
3. 验证码循环改为显式预算计数；提交前自动换图最多重试 3 次，不消耗有效图片预算。
4. `captcha_max_images` 默认值从 18 提到 30，主程序与 manifest 的默认值对齐。
5. 增加自动换绑阶段日志，日志只写阶段、不写凭据。

### v1.2.3：任务状态和底栏导航加固

1. 新增 `task-signed-first-day.png`，只取第一天奖励圆内 45×45 勾选标记；“已签到”不再依赖任何账户可变的金币余额。
2. 用生产 run `56` 已签到页回放分类：`nav≈1.000`、`layout≈0.998`、新 `signed=1.000`，结果为 `task_signed`。
3. 新增 `_navigate_task` 45 秒有界状态机，只在 `home` / `my_logged_in` 已知安全界面重试任务底栏，并可关闭延迟公告；在 `unknown` 或登录表单上不盲点。
4. 签到点击后的后置状态等待从 30 秒放宽到 60 秒。
5. 主脚本与脚本货架 seed 同步为完全相同的 38 个非运行时文件。
