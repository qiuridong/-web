# 动漫共和国验证码登录与 VPS 签到自动化

## 结论

- **已直接证明能够自动登录。** 在 UK 官方 Android Emulator 的一次性辅助用户中注销原会话后，脚本自动浏览验证码，识别并提交一张高置信乘法题，服务端登录成功；返回后可见登录用户和金币。辅助用户随后已删除，设备已切回 owner 用户 `0`。
- **已直接证明能够签到。** 真实点击任务中心签到后出现“已连续签到 1 天”成功弹窗，金币发生对应变化；脚本随后在 owner 会话上两次识别到“已签到”并幂等返回成功。
- **手机不需要 root。** 当前生产实现只使用标准 ADB shell、截图、点击、文本输入和按键，设备安全合同锁定 `emulator-6554`、`720x1280@320`、API 34、App `1.0.0.7`。
- **VPS 长期自动化与 Emulator 按需生命周期均已上线。** 生产 run `46` 从 Emulator 完全关闭状态开始，自动冷启动 `poc34`、复核 AVD/配置账号/当前昵称三重绑定、幂等确认“今日已签到”，随后自动关机。2026-08-25 又升级到 `dmgongheguo` v1.2.1：替换单个账户时只需由管家下发新账号密码，Agent 会自动清理旧 App 会话并重建绑定；详见 [2026-08-25 自动换绑记录](2026-08-25-动漫共和国管家下发自动换绑.md)。

## 范围

本次选择“原版 App + 官方 Android Emulator + ADB UI 自动化”，没有继续依赖 native 签名逆向。交付范围包括：

1. 本地高置信算术验证码识别器；
2. 登录态识别、邮箱登录、验证码刷新/提交和登录后置条件；
3. 任务中心“待签到 / 成功弹窗 / 已签到”三态幂等签到；
4. 主仓库和脚本货架 seed 双份插件；
5. UK VPS 远程 agent、主面板脚本、加密实例和定时调度；
6. systemd 按需启停、固定端口全局串行锁和每账户独立 AVD 绑定；
7. 离线验证码、UI 模板、沙箱协议和生产真机回归。

## 实现

### 1. 验证码策略

文件入口：

- `scripts/dmgongheguo/main.py`
- `scripts/dmgongheguo/helpers/captcha_solver.py`
- `scripts/dmgongheguo/assets/`

识别器使用独立 Python 3.12 OCR venv，固定依赖 `ddddocr==1.6.1`、ONNX Runtime、OpenCV headless、Pillow。策略为 fail-closed：

- 多阈值数字识别投票；
- 局部运算符模板与整行 OCR 双通道交叉确认；
- 只允许唯一、完整的乘法 token 链；
- 加、减、除、两位数边界不清、歧义数字或低置信图片只刷新，不提交猜测；
- 提交前再次核对验证码像素指纹，图片变化则放弃本次答案；
- 默认最多查看 18 张图片、真正提交最多 2 次；
- 刷新固定节流 12 秒，避免服务端“获取问题过于频繁”。

该策略的目标不是强行回答每一道题，而是在验证码随机序列中等待可确认的乘法题，以低误提交率换取可重复的整体登录成功率。

### 2. 登录与签到状态机

- 复用前台 App，避免 arm64 App 在 x86 NDK translation 下每次冷启动约 90 秒；只有 App 不在前台才启动 Splash Activity。
- 使用归一化相关系数识别固定安全界面，避免灰色禁用登录表单被平均背景色误判成“我的”页。
- 登录提交后等待真实后置条件；若服务端已经完成登录但旧登录表单仍覆盖路由栈，等待后退一次再复检登录态。
- 每日签到先进入任务中心：
  - `task_signed`：直接成功，不重复点击；
  - `task_ready`：只点击一次签到按钮；
  - 点击后必须出现成功弹窗和/或 `task_signed`，否则返回失败。
- 未知界面不会盲点每日唯一动作。

### 3. 运行环境

- ADB：`/opt/android-sdk/platform-tools/adb`
- serial：`emulator-6554`
- 设备：720×1280、density 320、API 34
- 包名：`com.shizi.tool.p3`
- App：`1.0.0.7`
- OCR：`/var/lib/signin-agent/data/instance-5/.ocr-venv`，约 396 MiB
- UK agent：`signin-agent` v1.1.1，systemd enabled + active

实例中的账号和密码由主面板 Fernet 加密写入 `config_blob`。生产检查确认密文中不含账号明文；中转 payload 和一次性 node token 文件均已删除，agent 配置权限为 `0600`。

### 4. Emulator 按需启停与账户隔离

- systemd 模板 `dmgongheguo-emulator@.service` 只由签到任务调用，状态为 `static`，不会开机常驻；使用固定 `-port 6554`，因此 ADB serial 始终是 `emulator-6554`。
- 任务先获取 `/run/lock/dmgongheguo-emulator-6554.lock`，再启动配置中的专属 AVD；同一节点上的多个 Android 实例即使计划时间碰撞，也只能严格串行。
- 启动后同时等待 ADB `device`、`sys.boot_completed=1`，并通过 `adb emu avd name` 核对实际 AVD，防止连接到错误的 Emulator。
- 账号绑定标记位于 AVD userdata 内，只保存 schema、包名、AVD 名、带域分隔的账号 SHA-256 和昵称字形 SHA-256，不保存账号明文、密码、昵称文字或截图。
- 已登录但无绑定标记、账号哈希不匹配、AVD 不匹配或昵称字形变化时一律在签到动作前停止；新账户必须使用独立、持久化 AVD。
- 正常成功、业务失败和 Agent 发送 SIGTERM 都会展开 Python `finally`，先 `sync` 再关闭 Emulator；systemd 的 `RuntimeMaxSec=22min` 是进程遭遇不可捕获终止时的第二层回收兜底。
- App 在 x86 转译环境下的真实冷启动可能超过 100 秒，v1.2.0 将“未知加载页”安全等待上限设为 240 秒；等待期间只截图识别，不点击未知界面。

## 风险与边界

1. **UI/App 版本锁定。** App 升级、分辨率/density/API 或任务中心布局变化时会安全失败，需要重新采集模板，不应降低阈值硬顶。
2. **验证码并非每张都回答。** 当前高成功率来自保守筛选和等待可确认乘法题；题库分布若长期不再出现乘法题，当次运行会失败而不是猜错。实例配置了一次平台级重试，间隔 300 秒。
3. **owner 登录态目前有效。** 生产 run `40`、`41`、`42`、`46` 验证的是已登录、已签到幂等路径；“登录态失效后的自动恢复”由同日辅助用户新登录实验直接证明。首次真正生产态失效恢复仍应观察日志。
4. **测试账号为临时凭据。** 长期账号确定后，在面板编辑 instance `5` 的 secret 字段即可，未提交的 secret 会保持原值；不要把账号密码写进仓库或进度文档。
5. **安装下载路由有现存缺陷。** `https://jb.aijiaxia.cc/agent-dl/install.sh` 当前返回前端 HTML，UK agent 本次改用主面板 `/opt/signin-panel/agent` 安装包经 SCP 部署；不影响已安装节点运行，但新增节点前应修复 Caddy 下载路由或继续使用校验后的安装包。
6. **Emulator 已改为按任务启停。** `poc34` 只在签到期间启动，结束或失败后自动关闭；run `46` 已从完全关闭状态完成冷启动→签到复核→关机闭环。`emulator-6554` 是固定启动端口产生的 ADB serial，不是随机生成，也不是用户真机序列号。
7. **低配机器的峰值需求仍存在。** 按需启停显著降低日常空闲占用，但签到期间 QEMU cgroup 仍约 3.28 GiB；建议 KVM、2 vCPU、至少 4 GiB RAM 并保留 swap。任务严格串行后 4 GiB 当前节点可运行，多账户不会因并行叠加内存，但会增加排队时间。
8. **账户替换与多账户共存边界。** 旧测试账户停用、正式账户接替时，v1.2.1 可在原 instance `5` 和 `poc34` 上自动换绑；如果两个账户要同时保留，仍需为第二账户创建独立持久化 AVD 和独立实例，并把计划时间错开 10–15 分钟。

## 回滚

1. 先在面板禁用 instance `5`，停止后续调度；
2. 执行 `systemctl stop dmgongheguo-emulator@poc34.service`，确认 ADB 和 QEMU 均已消失；模板本来就是 `static`，无需 disable；
3. 脚本级回退使用 `/opt/signin-panel/backups/manual/dmgongheguo-v1.1.0-before-ondemand-20260824-082114`，同步回 Agent 后再扫描；旧版要求 Emulator 常驻，只有确实回退时才按旧运行方式重新启动；
4. AVD 级回退使用 `/root/.android/avd-backups/poc34-before-ondemand-20260824-152020`，必须在 Emulator 关闭时操作并保留当前副本；
5. 如需撤销 UK 节点，执行 `systemctl disable --now signin-agent`；实例解绑/删除后再删除 node `4`；
6. 数据库级回退使用上述 SQLite online backup，回退前先停止 backend 并另做当前库备份；
7. Android owner 会话和 App 数据未被清除，不需要设备 root 回滚。
