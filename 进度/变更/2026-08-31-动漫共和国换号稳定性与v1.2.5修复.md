# 动漫共和国换号稳定性与 v1.2.5 修复

> 日期：2026-08-31
> 范围：生产面板 instance `5`、UK Agent、`poc34` AVD、换号自动登录与真实签到
> 结论：v1.2.5 已部署；真实管家 run `96` 完成“未登录 → 自动验证码登录 → 建立三重绑定 → 实际点击签到”，run `97` 再次冷启动后复用登录和绑定成功。

## 1. 生产时间线与证据边界

本轮同时读取主面板 SQLite、backend 容器日志、UK Agent/Emulator systemd 日志和 AVD 运行态，结论如下：

- instance `5` 仍绑定节点 `uk-9950x-android`，`cron=20 8 * * *`、`timeout=1200`、`random_delay_sec=0`、`auto_rebind_account=true`，当前账号和密码均已在 Fernet 加密配置中设置；全程未输出明文。
- run `68`（08-27）、`80`（08-29）、`85`（08-30）、`90`（08-31）虽然显示成功，但结果均为 `already_logged_in=true`、`already_checked_in=true`。这些记录只能证明脚本识别了“已经登录/已经签到”，不能证明当天登录或签到动作由脚本完成；这与用户说明“有几次成功是手工签到”一致。
- run `74`、`75`（08-28）均在 App 全冷启动阶段连续 `240s` 为 `unknown`；没有保留当时截图，因此不能把具体页面反推成已证明事实。
- 用户在 08-31 08:37（Asia/Shanghai）保存新配置后，run `91` 在 Emulator 冷启动时因一次 `adb get-state` 类调用 `TimeoutExpired` 直接终止。
- run `92` 已启动 App，但延迟公告连续吞掉固定坐标触摸，达到旧的 6 次上限后终止。
- 08:41 再次保存配置后，run `93` 已确认账号哈希变化，成功执行 `force-stop → pm clear → 删除旧绑定 → sync`，但从“旧绑定已清理”到报“仍不是未登录状态”只经过约 4 秒。

## 2. 根因

### 2.1 换绑后的旧画面被当成真实登录态

run `93` 的 `pm clear` 本身成功，失败发生在清理后的再次启动窗口：

1. 旧代码在 `_launch_app()` 中先读 `dumpsys activity`；只要仍看到目标 Activity 为 resumed，就直接返回，不重新执行 `am start`。
2. `pm clear` 返回 `Success` 后，旧 Activity 记录和最后一帧 framebuffer 仍可短暂残留。
3. `_dismiss_announcements()` 把这张旧“已登录”画面当成 App 已就绪，随后 `_navigate_my()` 立即返回 `my_logged_in`，触发安全停止。

直接复核：run `93` 已把 App 数据和绑定清空；随后在同一 AVD 上只读/受控启动，设备只有 Android user `0`，绑定标记不存在。真实页面经过约 `67s` 才按 `unknown → announcement×2 → home → my_logged_out` 到达未登录页。这证明清理有效，也证明 4 秒内看到的“已登录”只是旧画面/Activity 瞬态，不是旧账号仍在 App 内。

### 2.2 冷启动 ADB 瞬时超时缺少总预算内重试

生命周期原本对 `adb` 的单次 `TimeoutExpired` 立即抛错，即使 systemd Emulator 仍在正常启动，也会整轮失败。run `91` 正好命中此窗口。

### 2.3 公告恢复按累计次数而不是连续失败处理

旧导航把多张合法公告和触摸丢失累计到同一个 6 次上限，且只重复一个坐标。run `92` 因此在 App 仍可恢复时提前停止。

## 3. v1.2.5 实施

- 自动换绑清理改为显式 `pm clear --user current`，清理后先回 HOME，刷新旧 framebuffer。
- `_launch_app(force=True)` 在换绑后绕过 resumed 快捷路径，并通过 `am start -S` 强制建立新进程/Activity。
- 清理后前 `15s` 忽略与旧页面相同的短暂分类，仍受总 `app_ready_timeout_sec` 约束；真实页面若最终仍为登录态，依旧 fail-closed。
- Emulator 启动阶段只对明确由 `subprocess.TimeoutExpired` 引起的 ADB 瞬时失败在总启动预算内重试；AVD 身份不匹配、命令非零等其它错误仍立即停止。
- 公告计数改为“连续公告”计数，预算提高到 9 次；每第三次在已确认 `announcement` 的前提下使用 BACK 兜底，页面一旦变化即重置连续计数。
- App 就绪、“我的”导航和任务导航新增不含账号/截图的 `surface/confidence/scores` 转移日志，后续可直接从管家日志判断具体失败步骤。
- manifest 升级至 `1.2.5`；主脚本与脚本货架 seed 的 38 个有效文件逐文件 SHA-256 一致。

- `scripts/dmgongheguo/main.py`

## 5. 真实脚本管家闭环

### run `96`：自动登录并实际签到

run `96` 由主面板 service 创建 pending run，UK Agent poll 领取；不是 SSH 直接运行脚本。

- `status=success`、`exit_code=0`、消息“动漫共和国签到成功”。
- 起点是 `already_logged_in=false`；脚本自动查看 11 张验证码，刷新 10 次，只提交 1 次高置信答案，并安全处理 1 次输入期间自动换图。
- `logged_in=true`，新 AVD/账号/昵称字形三重绑定写入并复核成功。
- `checked_in=true`、`already_checked_in=false`、`success_dialog_seen=true`：这是脚本实际点击签到并看到成功后置条件，不是把用户手工签到误记为成功。

## 6. 风险边界与回滚

- run `96` 已直接证明当前账户的自动验证码登录和实际签到，run `97` 已直接证明绑定与会话跨 Emulator 重启持久；不再把“已手工签到”的幂等成功当作自动化动作证据。
- 已直接修复并真实验证 run `93` 的清理后旧画面问题。run `91` 的 ADB timeout 与 run `92` 的公告丢触摸已补回归和生产代码，但本次两次成功运行没有再次强制制造同样的瞬态故障。
- 回滚时恢复上述 v1.2.4 脚本目录，重新扫描并让 Agent 下次运行同步；一般代码回滚不覆盖当前数据库，也不删除已经验证的新账户绑定。必要时才使用 online-backup 数据库文件。
