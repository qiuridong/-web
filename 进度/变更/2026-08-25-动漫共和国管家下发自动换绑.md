# 动漫共和国管家下发自动换绑

## 结论

- `dmgongheguo` 已从 v1.2.0 升级到 **v1.2.1**。
- 情况 A（旧测试账户停用、正式账户接替）现在只需编辑原 instance `5`，同时填写新邮箱和新密码；不需要 SSH、手工删除绑定、新建实例或新建 AVD。
- 管家在任务中把加密配置下发给 UK Agent。插件检测到配置账号哈希与 `poc34` 绑定哈希不同后，在 Emulator 全局锁内完成一次性自动换绑。
- 情况 B（两个账户同时保留）仍遵循“一账户一 AVD 一实例”，本次改动没有降低多账户隔离边界。

## 用户操作

1. 在签到管家编辑 `DMG Daily Check-in`（instance `5`）；
2. 把“邮箱账号”改为新账户；
3. **同时重新输入新账户密码**；secret 输入框中的旧密码占位仍对应旧账户；
4. 保持“账号变化时自动换绑”为开启；
5. 保存后点击“立即运行”，或等待下一次计划运行。

账号未变化、只更新密码时不会清理 App；新密码只在登录态失效后用于恢复登录。

## Agent 自动流程

1. 按 v1.2.0 生命周期启动配置中的 AVD，并核对 ADB serial、实际 AVD、分辨率、API 和 App 版本；
2. 读取旧绑定，先验证 schema、包名、AVD 名、账号哈希格式和昵称签名格式；
3. 只有“容器仍属于当前 App/AVD，但账号哈希发生变化”才进入自动换绑；App/AVD 不匹配或标记损坏仍 fail-closed；
4. 若旧账户仍登录，先提取当前昵称字形并与旧绑定复核，防止在未知登录身份上执行清理；
5. 确认管家同时下发了非空密码；
6. 执行 `am force-stop`、`pm clear com.shizi.tool.p3`、删除旧绑定标记和 Android `sync`；不卸载 APK、不删除 AVD；
7. 重新启动 App，并确认已进入未登录状态；
8. 使用管家下发的新账号密码完成验证码登录；
9. 登录成功后才写入新账号哈希和新昵称字形签名；
10. 继续执行幂等签到，最后在 `finally` 中关闭 Emulator。

成功结果新增：

```json
{
  "account_binding_verified": true,
  "account_rebound": true
}
```

如果旧 App 数据已经清理、但新账号因密码或验证码失败而尚未登录，失败结果会记录：

```json
{
  "account_rebind_attempted": true
}
```

修正面板凭据后再次运行即可从未登录状态继续；不会回退去签到旧账户。

## 安全边界

1. `auto_rebind_account=true` 是生产默认值；设为 `false` 时账号变化仍只报错，不清理旧会话。
2. App/AVD 绑定容器不一致、绑定 JSON 损坏、账号哈希格式错误、旧昵称签名不一致时都不会自动清理。
3. 新账号绑定只在真实登录成功并提取新昵称字形后写入，避免把错误凭据登记成成功绑定。
4. `pm clear` 会清除原账户在 App 中的本地会话。用户必须同时填写新邮箱和新密码；若输入有误，本轮安全失败，原账户会话不会继续被使用。
5. 账号和密码仍只存在面板 Fernet 加密 `config_blob` 与单次 Agent 任务内存中；日志、绑定标记、结果和仓库均不保存明文。
6. 单账户“替换”允许复用 `poc34`；多账户“共存”仍必须使用不同 AVD，防止会话和 userdata 混用。
